两个易错点 
脱敏是返回掩码（如 138****6621），不是返回空值；日志不得留明文。 
越权返回 POLICY_DENIED 并留痕，不要返回 404，否则与「数据不存在」无法区分。 
 
2.3  一次典型处置 
①  理解：解析问题，识别订单号、异常类型与诉求；信息不足时追问，不猜测。 
②  取证：调用工具取订单、库存、供应商画像、相似工单；每个结论带来源。 
③  计算与检索：金额、进位、运费、补货量走纯函数工具；条款走检索，只引用检索到的条款号。 
④  建议：生成建议卡：动作、参数、依据、风险、置信度、是否需人工确认；规则不过直接否决。 
⑤  复核：用户确认或修改；修改进入标注集，成为技能沉淀与提效对比的素材。 
2.4  业务规则 
完整规则见附录 B（R1–R14）。三条最容易错： 
•  进位。计费体积向上取整到整数立方尺：3.2 → 4，0.4 → 1。 
•  舍入。金额用 DECIMAL 定点 + ROUND_HALF_UP，禁止用 JS number 累加。 
•  补货。补货量 =（安全库存×2 − 当前库存 − 在途），向上取整到 MOQ 整数倍；除数为 0 返回 
E_DIV_ZERO。

import { defineTool } from '@deepseek-ai/dsh-tools' 
 
ctx.tools.register(defineTool({ 
  name: 'order.lookup', 
  description: '按订单号查询采购订单与履约状态。不适用于按供应商汇总。', 
  parameters: { 
    orderId: { type: 'string', required: true, description: '采购订单号，如 PO-20261013-0042' }, 
    tenantId: { type: 'string', required: true, description: '运行时注入，模型不可自填' }, 
  }, 
  output: { 
    schema: { type: 'object' }, 
    render: (_args, v) => [{ type: 'text', text: summarize(v) }], 
  }, 
  async execute(args, exec) { 
    const row = await db.order.get(args.orderId, args.tenantId, exec.signal) 
    if (!row) throw new ToolError('NOT_FOUND', '订单不存在或不属于当前租户') 
    return { ...row, provenance: [{ table: 'orders', rowId: row.id }] } 
  }, 
})) 
 
•  description 写清适用与不适用场景，模型选错工具多半是因为这段没写清楚。 
•  参数校验交给平台，你只处理业务错误；错误码统一为 NOT_FOUND / INVALID_ARGUMENT / POLICY_DENIED 
/ UPSTREAM_TIMEOUT。 
•  所有结果带 provenance（表名 + 行 id），这是「引用可溯」的数据基础。 
4.3  用 guard 做策略 
租户隔离与字段脱敏不要写在每个工具里，用平台的工具守卫在调用前统一拦截。 
ctx.tools.guard((call, next) => { 
  const { name, args } = call 
  if (name === 'supplier.profile' && args.tenantId !== ctx.session.tenantId) { 
    return { deny: 'POLICY_DENIED: 跨租户访问' } 
  } 
  if (args.tenantId === 'T-002' && !ctx.session.roles.includes('overseas')) {

  }

附录 C  技能样例说明 
一份好的技能应当让模型少走弯路：明确先调什么、参数从哪来、什么情况停手。反例是「把整
段对话贴进去」，那只是历史记录，不是技能。 
•  触发条件写得窄一点，宁可两份技能也不要一份万能技能。 
•  每个步骤只写「调哪个工具、传什么参数」，不要写大段业务解释。 
•  护栏单独成段，写成「如果……就停止并升级」的句式。 
•  末尾加一条反例：本次踩过的坑，下次怎么避开。 
附录 D  常见问题 
•  需要改 DSH 代码吗？  不需要。工具通过插件注册，技能通过 SKILL.md 落盘，配置通过 profile。 
•  模型能换吗？  不能。固定为 DeepSeek V4.1 flash，评测与提效数据都在同一模型下比较。 
•  技能是代码吗？  不是。技能是给模型读的指令文件，执行仍通过工具；护栏由技能文本与 guard 共同保
证。 
•  怎么证明技能生效？  技能 B 由 Agent 写入后，下一次会话的 trace 里应出现该技能的加载与更短的工
具序列。 
•  A/B 怎么保证对照干净？  把 .dsh/skills 临时移走跑 A 组，再放回跑 B 组；同一批工单、同一模型、
同一数据。 
•  没做完怎么办？  按已交付部分验收。建议优先保证「一次完整问答 + 一份技能 + 一张 A/B 表」。 
 
 
如有疑问，请在开考后 15 分钟内提出；开考 15 分钟后只处理环境故障。
